# Design variant — no design

## Detect

No Figma link and no images in the request or the requirement — a behaviour-only change, or UI the
user expects to follow existing patterns. Provisional until the user confirms in Step 3's first group.

## Fetch

Find the closest existing screens and components in the repo that the change should look like, and
name them in Step 3 for the user to confirm as the reference.

## Tokens and states

Use only existing design-system components and tokens. Any new visual element is a Step 3 question,
since there is nothing to derive it from.

## Fidelity source

Two checks instead of a mockup: before/after screenshots of the touched screens (nothing changed that
the spec does not ask for), and consistency with the confirmed reference screens (same components,
spacing scale and type styles). Capture the "before" set at the start of Step 6, per state ×
viewport cell, asking how to start the app if the profile and scripts do not say.

## Pitfalls

- "No design" often means "the designer has not got to it yet" — ask whether to wait.
